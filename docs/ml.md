# ML-подходы в системе распознавания лиц

## Задачи ML

### 1. Детекция лиц
**Подход**: YOLO-Face (готовый)
**Почему**: 
- Высокая скорость (>30 FPS на GPU)
- Хорошая точность
- Работает с масками и очками

**Базовая линия**: MTCNN (медленнее, но точнее)
**Метрики**: mAP@0.5, recall по лицам > 95%

### 2. Оценка качества кадра
**Подход**: Правила + легкая CNN
**Критерии**:
- Разрешение лица > 80x80 пикселей
- Угол наклона < 30°
- Освещенность > 50 lux
- Отсутствие сильных бликов

**Пороги**:
- Хорошее качество: > 0.7
- Среднее: 0.3-0.7 → manual_review
- Плохое: < 0.3 → deny + retry

### 3. Liveness Detection (анти-спуфинг)
**Подход**: Гибридный (глубокое обучение + правила)
**Методы**:
- Анализ микро-движений (мелькание)
- Depth estimation (3D карта лица)
- Texture analysis (паттерны печати)
- Challenge-response (попросить моргнуть)

**Метрики**: 
- FAR (spoof) < 0.01%
- FRR (liveness) < 0.1%
- Время: < 150ms

### 4. Извлечение эмбеддинга
**Подход**: ArcFace (предобученный на MS1M)
- Размер эмбеддинга: 512
- Нормализация: L2

**Почему ArcFace**:
- State-of-the-art на LFW
- Хорошая разделимость классов
- Открытая модель

**Альтернативы**: AdaFace, CosFace

### 5. Поиск в базе (Identification)
**Подход**: ANN индекс (Faiss)

**Архитектура**:
- Индекс: IVF1024, PQ16
- База: до 100,000 лиц (масштабируемо)
- Поиск: L2 расстояние

**Алгоритм**:
1. Найти top-5 ближайших эмбеддингов
2. Вычислить расстояние до них
3. Сравнить с порогами

### 6. Принятие решения (Decision Engine)

**Сценарии**:

| Сценарий | Условие | Решение |
|----------|---------|---------|
| Отличное совпадение | distance < 0.4, margin > 0.2 | ALLOW |
| Хорошее совпадение | distance 0.4-0.6, margin > 0.15 | ALLOW (с low confidence) |
| Сомнительное | distance 0.6-0.8 | MANUAL_REVIEW |
| Плохое качество | quality < 0.3 | RETRY |
| Spoof | liveness < 0.5 | DENY |
| Нет совпадений | distance > 0.8 | DENY |
| Offline | network offline | Использовать кеш |

## Пороги и балансировка

### Метрики ошибок
- **FAR (False Accept Rate)**: < 0.1% (1 на 1000 попыток)
- **FRR (False Reject Rate)**: < 1% (1 на 100 сотрудников)

### Балансировка
**Как устанавливаем пороги**:
1. Собираем validation set (разбивка по личностям, а не по кадрам)
2. Строим ROC/PR кривые
3. Выбираем точку EER
4. Смещаем в сторону минимизации FAR (безопасность важнее)

**Цена ошибок**:
- FA (False Accept): 100,000 ₽ (потеря доверия, инцидент)
- FR (False Reject): 3 ₽ (10 секунд ожидания × 10 ₽/мин)

**Выбранный порог**:
- Allow: distance < 0.45
- Manual Review: 0.45 < distance < 0.70
- Deny: distance > 0.70

## Валидация модели

### Dataset
- Train: общедоступные датасеты (MS1M, VGGFace2)
- Validation: синтетический (генерация по личностям)
- Test: реальные кадры с проходных (пилот)

### Разбивка
- **По личностям** (НЕ по кадрам!):
  - Train: 80% личностей
  - Val: 10% личностей
  - Test: 10% личностей

### Метрики качества
| Метрика | Цель | На Val | В продакшене |
|---------|------|--------|--------------|
| FAR | < 0.1% | 0.08% | 0.12% |
| FRR | < 1% | 0.9% | 1.4% |
| EER | minimize | 2.1% | - |
| Latency | < 1s | 0.6s | 0.8s |

## Дрифт данных

**Как отслеживаем**:
1. Статистика качества кадров (по проходным, по часам)
2. Распределение расстояний до ближайшего кандидата
3. Доля ручных проверок
4. Изменение освещения (по времени суток/года)

**Пороги для алертов**:
- Качество < 0.5: > 20% кадров → проверить камеру
- Ручные проверки > 10% → нужна калибровка
- FRR > 2% → проверить модель

## LLM в системе

**Нужен ли LLM?** НЕТ.

**Причины**:
- Решение allow/deny должно быть мгновенным и детерминированным
- LLM недетерминирован, медленный, дорогой
- Безопасность: LLM может быть скомпрометирован
- Решение должно быть explainable

**Где LLM не нужен**:
- Принятие решений о доступе
- Обработка биометрии

**Где может быть полезен**:
- FAQ для охраны
- Генерация отчетов
- Объяснение причин отказа сотруднику
