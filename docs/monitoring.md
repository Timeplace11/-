## Алерты

### Критические (Critical)
1. **FAR > 0.1%** → Остановить систему, полный аудит
2. **Security incident** → Блокировка доступа
3. **All gate offline** → Переключение на карты

### Важные (High)
1. **FRR > 3%** → Проверить калибровку
2. **Handover > 10%** → Проверить модель
3. **Latency > 2s** → Усилить ресурсы

### Информационные (Info)
1. **Quality score drop** → Проверить камеры
2. **Network latency** → Проверить сеть
3. **Cache sync delay** → Проверить синхронизацию

## Audit Trail

### Что логируется
1. **Каждое решение**: event_id, gate_id, employee_id, decision, score
2. **Ручные проверки**: кто, когда, решение, причина
3. **Изменения базы**: добавление/удаление сотрудников
4. **Инциденты**: время, описание, действия
5. **Системные события**: перезагрузки, ошибки, апдейты

### Хранение
- Audit log: 7 лет (юридические требования)
- Raw images: 30 дней (для расследований)
- Embeddings: пока сотрудник активен + 30 дней

## Расследование инцидентов

### Процесс
1. Получить event_id
2. Собрать все данные по событию
3. Посмотреть raw image (если сохранено)
4. Проверить логи модели
5. Принять решение: ошибка модели или инцидент

### Пример расследования

Время: 2026-07-31 08:52:14
Проходная: gate-2

Решение: ALLOW
Score: 0.81

Анализ: нормальный проход

## Отслеживание деградации

### По проходным
- Если gate-1 FRR растет, а gate-2 нет → проблема на конкретной проходной
- Проверить: камера, освещение, позиционирование

### По времени
- Утром качество хуже (контровый свет) → адаптировать пороги по времени
- Зимой/летом разные условия → сезонная калибровка

### По сотрудникам
- Новые сотрудники могут быть хуже распознаны → дообучение
- Старые сотрудники с изменением внешности → обновление эмбеддинга
